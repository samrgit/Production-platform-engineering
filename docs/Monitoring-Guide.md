# Monitoring Guide

## Overview

This project implements a production-oriented monitoring stack using Prometheus, Grafana, Node Exporter, cAdvisor, and Alertmanager.

The monitoring platform provides centralized visibility into host resources, container performance, infrastructure health, and alert management.

---

# Monitoring Architecture

The monitoring stack consists of the following components:

| Component | Purpose |
|----------|---------|
| Prometheus | Metrics collection and alert evaluation |
| Grafana | Dashboard visualization |
| Node Exporter | Host system metrics |
| cAdvisor | Docker container metrics |
| Alertmanager | Alert management and routing |

---

# Prometheus

Prometheus continuously collects metrics from configured scrape targets.

Configured scrape targets include:

- Prometheus
- Node Exporter
- cAdvisor

Configuration file:

```
monitoring/prometheus/prometheus.yml
```

Alert rules:

```
monitoring/prometheus/alerts.yml
```

---

# Grafana

Grafana connects directly to Prometheus as its primary data source.

The platform includes:

- Node Exporter Dashboard
- cAdvisor Dashboard
- Custom Production Dashboard

The custom Production Dashboard provides:

- Prometheus Status
- Node Exporter Status
- cAdvisor Status
- Host CPU Usage
- Host Memory Usage
- Container CPU Usage
- Container Memory Usage
- Running Containers
- Active Alerts

---

# Node Exporter

Node Exporter collects host-level metrics.

Examples include:

- CPU utilization
- Memory utilization
- Filesystem usage
- Network statistics

Default endpoint:

```
http://localhost:9100/metrics
```

---

# cAdvisor

cAdvisor provides container-level metrics.

Collected metrics include:

- CPU usage
- Memory usage
- Filesystem usage
- Network usage

Default endpoint:

```
http://localhost:8081
```

---

# Alertmanager

Alertmanager receives alerts generated by Prometheus.

Current configuration:

```
monitoring/alertmanager/alertmanager.yml
```

Current alert rules include:

- PrometheusDown
- HighCPUUsage
- HighMemoryUsage
- ContainerDown

Alerts are visible through:

```
http://localhost:9093
```

---

# Monitoring Workflow

The monitoring workflow follows these steps:

1. Node Exporter and cAdvisor expose metrics.
2. Prometheus scrapes the configured targets.
3. Prometheus evaluates alert rules.
4. Alertmanager receives firing alerts.
5. Grafana visualizes collected metrics.

# Health Verification

Verify Docker containers:

```bash

```

Verify Prometheus targets:

```
http://localhost:9090/targets
```

Verify Prometheus rules:

```
http://localhost:9090/rules
```

Verify Prometheus alerts:

```
http://localhost:9090/alerts
```

Verify Alertmanager:

```
http://localhost:9093
```

# Custom Dashboard

A custom Grafana dashboard was developed specifically for this project.

The dashboard provides a centralized operational overview of the monitoring stack and infrastructure health using custom PromQL queries instead of relying solely on imported community dashboards.

---

# Conclusion

The monitoring platform provides complete observability for both host and container environments by combining metrics collection, visualization, alerting, and health monitoring into a single production-oriented monitoring solution.
